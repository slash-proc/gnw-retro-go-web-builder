# Library: where the additional options live

Four boards, varying one thing. Everything else is held constant on purpose: same chrome, same
console chip strip, same twelve games, same coverflow, same summary dock. A comparison is only
worth making when one variable moves.

Generated by `build-options.py` on top of `shell.py`, for the reason `overview-v2` gives:
"hand-copying them is how a board set drifts".

## What is held constant, and where it came from

Fixtures are lifted from `docs/design/mockups/Roms.dc.html` and `RomsOptions.dc.html`, not
re-picked: the same twelve rows with their systems, sizes and states, the same console counts
(All 137, NES 63, Genesis / Mega Drive 22, GW 25, Master System 9, PC Engine 7, Game Gear 6,
Homebrew 3), the same 3D coverflow, the same dock. The options content is the shipped one at
full strength on every board: cover source, variant, preview, apply, the drop target and the
scraper budget; the SRAM and slot tabs with the preview, the written date and the download;
and the cheats presets, manual entry and configured count.

**Cheats is drawn at the same weight as saves on all four.** It is a device feature, not a
sub-option, so it keeps both its presets and its manual entry everywhere.

## The four

### `OptionsRail`: a persistent inspector column

The options stop being a thing you open. A third column is always there, showing whatever the
carousel selected. Nothing is behind a disclosure, so nothing is forgotten, and a fourth
section arrives by appending to the column. Moving the options out of the right column also
gives the coverflow the full 948px, so no card is clipped.

**What it trades away.** Three sections at full strength are about 1110px of column against
roughly 1015px of page, so the rail scrolls and the third section is cut by the page edge.
That is drawn rather than hidden by shrinking the sections until they fit, because it is the
point: **this is the shape that gets worse as options are added**, which is the opposite of
what was asked for. A fifth section makes it worse again.

**At risk from the keep-everything list:** the dock's Additional options disclosure is gone,
because a control that opens nothing is worse than no control. The list also loses width to
the third column.

### `OptionsSheet`: a sheet with its own section rail

The one shape that still works at ten sections. A vertical rail lists them and one is open at
a time, so page height stops limiting how many there can be: a new section costs one rail row,
not another 350px of column. The carousel sits above the sheet so there is still a sense of
which game is being edited.

**What it trades away.** The sheet replaces the list while it is open, so you cannot see what
you selected while you configure it.

**At risk:** the games list, while the sheet is open.

**One speculative item, marked.** `Save states` is drawn beside `Saves` and labelled *not
built*. The owner named them as separate features ("Cheats are a genuine feature of the device
just like saves/savestates") and today they share one section, with SRAM and the numbered slots
behind the same tabs. **No artboard draws it and no code ships it.** It is on this board only,
because showing that the rail scales is the whole thesis and three items does not show it. If
that is unwelcome, it is one line in `build-options.py`.

### `OptionsInline`: the row opens where it is

No drawer, no rail, no modal. A row opens in place and its options are underneath it, so the
thing being configured and the thing doing the configuring are never in different parts of the
screen. That is the complaint the drawer earned: it rose from the bottom bar, on the opposite
edge from the row it acted on. The carousel goes full width above the list, since there is no
right column competing for it.

**What it trades away.** The list stops being a list while a row is open. Games below the open
row are pushed down by about 420px, so the shape of the page changes under you every time you
open one.

**At risk:** this is the weakest of the four on extensibility. A fourth section makes every
expansion taller and there is no rail to hang it on. Three columns is roughly the ceiling at
1440, so it fails the specific thing that was asked for.

### `OptionsModal`: the drawer promoted to a modal

The drawer was right about being one place for all of this and wrong about being a drawer: it
shares the bottom edge with the summary, so opening one closes the other, and it is half a
screen tall while the thing it configures is at the top. A modal takes the whole attention
instead of half the page, and tabs are the cheapest extension point there is. The library stays
behind it, dimmed, so the selection is not thrown away by opening the thing that acts on it.

**What it trades away.** It is a modal. You cannot flick the carousel to the next game while it
is open, so configuring five games is five open-and-close cycles.

**At risk:** tabs run out sooner than a rail does. Four fits comfortably at this width, six
starts to crowd, and there is no answer at ten.

## If you are distilling

The honest read across the four: **`OptionsSheet` is the only one that answers "extendable"
without a ceiling**, and `OptionsRail` is the only one that answers "never hidden". They
disagree, and the disagreement is the actual decision. `OptionsInline` is the best answer to
"the drawer was nowhere near the thing it acted on" and the worst answer to extensibility.
`OptionsModal` is the smallest change from what ships.

A fifth board worth drawing, if none of these land: the sheet's vertical rail *inside* a
persistent right column, so it is both always visible and bounded. It is not drawn here
because it was not asked for and inventing a fifth direction unasked is how the last pass
missed.

## Not verified

**Nothing here has been seen.** There is no headless browser in this environment, so the
layout arithmetic was checked by calculation rather than by looking: column widths sum inside
1360px on every board, and every coverflow's outer card reach was computed against its
container half-width (rail 420 vs 474, sheet 235 vs 680, inline 285 vs 680, modal 278 vs 280,
all fit). HTML nesting is parser-verified on all four. Vertical rhythm, the rail's fade edge
and the modal's centring are reasoned, not observed.

`support.js` is referenced by every board in this repo and **is not checked in anywhere**, so
there was nothing to copy beside these boards; the canvas runtime supplies it. The three image
assets are copied in from `overview-v2/`.

These boards are not on the main canvas and `apps/web/test/artboard-index.mjs` ignores this
directory, per the rule in `mockups/README.md` that the approved set holds approved boards only.
